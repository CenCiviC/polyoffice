# 남은 일

구글 문서를 기준선으로 삼은 작업의 현재 위치. 전수 목록과 근거는
[GDOCS-FEATURES.md](GDOCS-FEATURES.md), 어휘 계약은 [IR-SPEC.md](IR-SPEC.md)에 있다.
이 문서는 **다음에 무엇을 어떤 순서로 할지**만 담는다.

기준선 18개 중 **11개 완료** — 1군을 전부 끝냈다. 링크 · 첨자 · 문단 여백 · 페이지 설정 ·
서식 지우기 · 낱말 수 · 개요 레일 · **목록 numbering** · **개요 번호** ·
**표 셀 테두리·세로 정렬** · **각주** · **머리말·꼬리말·쪽번호**, 그리고 계획 밖이었지만
필요했던 **읽기(Rust 리더 5종)**.

형태 표기는 GDOCS-FEATURES.md와 같다 — **A** 새 어휘 · **B** 속성 · **C** 백엔드 ·
**D** 편집기 · **E** 뷰어.

방금 끝난 것: **07 목록 numbering**과 **08 개요 번호**. 둘 다 `"• "`·번호를 본문 글자로 박던
강등을 걷어내고, 세 포맷 모두 **전역 정의 테이블 + 문단 바인딩**으로 갔다(목록은 중첩 수준까지).
개요 스킴은 한글 공문서 관행 `1. → 가. → 1) → 가) → (1) → (가)`이고, 진실원은
`OUTLINE_SCHEME` 배열 하나 — 뷰어 CSS counter도 백엔드 셋의 numbering 정의도 거기서 나온다.

hwpx 문법(`heading type="NUMBER"|"OUTLINE"`, `paraHead`의 `^n` 치환, `HANGUL_SYLLABLE`)은
추측이 아니라 **실물 한글 문서에서 확정**했다. 매핑은 [IR-SPEC.md](IR-SPEC.md) 표에,
검증은 `bun run list-sim`·`bun run outline-sim`에 있다.

09는 셀 테두리·세로 정렬을 IR 어휘로 올리고(`border`·`vertical-align`) 편집 UI(셀 서식
다이얼로그)까지 붙였다. 하다가 **셀에 `<p>` 없이 쓴 글자를 세 백엔드가 통째로 버리던 버그**를
찾아 같이 고쳤다 — 왕복 검증이 `td`를 안 봐서 오래 통과했다(이제 본다).

05는 TODO에 "쓰기가 완비"라고 적혀 있었지만 실제로는 **hwpx만** 각주를 쓸 줄 알았다 —
docx·odt는 `doc-footnote`를 통째로 버렸다. UI만 붙이면 두 포맷에서 각주가 사라진 채
나가므로 쓰기(docx `footnotes.xml`, odt `text:note`)까지 같이 했다. 리더가 참조에
`1)`을 **글자로** 박던 것도 걷어냈다(규칙 2) — 이제 참조의 `<a>`는 비어 있고 번호는
뷰어 counter가 그린다. 참조를 지우면 짝도 지워진다(`pruneFootnotes`).

10도 hwpx 매핑을 실물에서 확정했다 — `hp:footer applyPageType` + `hp:autoNum numType="PAGE"`.
머리말·꼬리말은 조판이 페이지마다 복제하고 `unpaginate`가 걷는다(각주 TAIL과 같은 패턴).
전체 쪽수만 hwpx에서 **강등**이다 — numType 값을 실물로 못 봤다.

가다가 찾은 세 가지도 같이 고쳤다. 전부 "조용히 사라지는" 종류라 왕복 검증에 걸릴
자리를 함께 만들어 뒀다.

| 무엇 | 어디 |
|---|---|
| 셀에 `<p>` 없이 쓴 글자를 세 백엔드가 통째로 버림 | `readBlocks`의 암묵 문단 · `expectedText`에 `td` 추가 |
| `<span>` 안의 `<sup>`·`<a>`·`doc-field`를 hwpx가 글자로만 긁음 | `inlineRuns`가 span에 재귀 |
| hwpx 리더가 `<hp:ctrl>`로 감싼 각주를 못 봄 | `hwpx.rs`의 ctrl 분기 |

**읽기 대칭**: 리더 넷(hwpx·docx·odt·**hwp**)이 개요 수준 · 목록(중첩 포함) · 셀 테두리 ·
머리말·꼬리말·쪽번호를 되읽는다. `bun run reread-sim`이 IR → 파일 → **다시 IR**을 세 포맷에서
전수 대조하고, 실물 문서에서도 확인했다 — 공공기관 배포 hwpx의 꼬리말·쪽번호·번호 목록,
`.hwp` 서식 문서의 셀 테두리(색까지)와 글머리표 목록. **남은 것은 `.doc` 하나** — 검증할
샘플이 없어 손대지 않았다.

## 2. 검증 부채

기능이 아니라 **확인이 안 된 것**. 지금 이 머신의 한계 때문에 막혀 있다.

| 막힌 것 | 필요한 것 | 풀리면 |
|---|---|---|
| ~~docx·odt를 외부 구현으로 열어본 적 없음~~ | ~~LibreOffice~~ | **풀렸다.** LibreOffice 25로 두 포맷을 PDF 렌더까지 확인했다 — 개요 번호(`1. 가. 나. 2.`) · 목록 재시작 · 각주 구분선 · 머리말/꼬리말 · 쪽번호 `1 / 1` · 셀 테두리 전부 화면과 같다 |
| ~~hwpx를 한글로 열어본 적 없음~~ | ~~한글이 있는 기기~~ | **반쯤 풀렸다.** 한글 2018로 열어 조판을 확인했고 그 자리에서 버그 넷을 잡았다 — 개요 번호(구역의 `outlineShapeIDRef`) · 표 열 폭 상속 · 표 행 높이 · 셀 여백(`hp:tc/@hasMargin`) · 머리말 여백. 개요·목록·표·각주·머리말·꼬리말·쪽번호·문단 여백·첨자 전부 화면과 같다 |
| **한글 2018은 hwpx 렌더링 자체가 망가져 있다** | 한글 2020+ 또는 한컴독스 | 진짜 한글이 만든 정부 hwpx(`samples/hwpx/*`)를 열어도 본문이 새까맣게 나온다 — `shadeColor="none"`을 검정으로, 색 속성을 BGR 역순으로 읽는다(그 파일의 `faceColor="#D0EAED"`가 화면에서 `#EDEAD0`으로 찍힌다). 같은 한글로 `.hwp`는 멀쩡하다. **색·글자 배경·각주 구분선은 이 기기로 판정할 수 없다** |
| hwpx 하이퍼링크 **쓰기**가 강등 상태 | 한글에서 링크 하나만 넣고 저장한 hwpx | `hp:stringParam name="Command"` 문법 확정 → 강등 제거 |
| 글머리표를 `hh:bullets`로 쓸 수 있는지 | 한글에서 글머리표만 넣고 저장한 hwpx | 지금은 번호 서식 문자열에 문자를 적어 대신한다. 확인되면 진짜 글머리표 테이블로 갈아탄다 |
| `.doc`의 개요·목록·셀테두리·머리말 읽기 | **`.doc` 샘플이 이 레포에 하나도 없다.** 생기면 sprm `POutLvl`(0x2640 추정)·`PIlvl`(0x260A)·`PIlfo`(0x460B)부터 확인한다 | 나머지 넷은 끝났다(`bun run reread-sim`). 샘플 없이 opcode를 추측하면 엉뚱한 문단이 제목이 된다 |
| `.hwp` 셀 세로 정렬 | LIST_HEADER 속성의 세로 정렬 비트 위치 | 테두리·문단머리는 hwp.js에서 근거를 찾았는데 이건 hwp.js도 안 읽는다. 지금은 기본값(가운데) |
| hwpx 전체 쪽수 강등 | 한글에서 꼬리말에 전체 쪽수만 넣고 저장한 hwpx | `numType` 값 확정 → docx·odt와 같아진다 |
| `.doc` 들여쓰기 sprm 미발화 | 들여쓰기가 있는 Word 97 문서 | `0x840F`/`0x8411` 검증 → README 표의 ◐를 ✓로 |
| 화면 회귀를 사람이 봐야 함 | — | `bun run shots`가 캡처·콘솔오류·표 컨텍스트 전환까지 보지만, **그림이 맞는지는 사람이 본다** |

`.hwp`·`.doc`의 하이퍼링크 읽기는 필드 구조라 미구현 — 검증 부채가 아니라 남은 기능이다.

## 3. UI 구조 — 새 기능이 요구하는 없던 영역

버튼이 아니라 **앱에 없던 화면 영역**이 필요한 것들. 개별 기능보다 이게 먼저 걸린다.

| 필요한 영역 | 무엇이 요구하나 | 걸리는 것 |
|---|---|---|
| 가로 눈금자 | 들여쓰기·탭 정지 | 배율이 iframe 안 `body.style.zoom`이라 크롬 쪽 좌표와 어긋난다 |
| 머리말·꼬리말 밴드 | 10번 | `paginate`가 만든 페이지마다 그리고 저장 전 제거 |
| 여백 경계선 | 여백 드래그 | 지금 `padding`만 있고 **눈에 안 보인다**. 10번의 선행 조건 |
| 셀 선택 상태 | 표 서식 일괄 적용 | 지금 "셀 선택" 개념 자체가 없다 — 캐럿만 있다 |

**문서가 iframe 안에 있다**(`previewRef.contentDocument`)는 게 공통 제약이다. 문서 좌표에
붙는 UI(눈금자·표 핸들·링크 팝오버)는 좌표를 환산하는 대신 **오버레이를 iframe 안에 그리고
저장 직전에 걷어내는 쪽**을 권한다 — `paginate`/`unpaginate`와 `table-ui`가 이미 쓰는 패턴이다.

모달·팝오버 계층은 v0.2에서 만들어 뒀다(`.scrim`/`.dialog`/`.seg`). 표 서식·목록 옵션·
줄간격 팝오버가 그대로 재사용하면 된다.

## 4. 나중 (3군)

단(열) 나누기 · 목차 · 수식 · 도형/글상자 · 이미지 줄바꿈·위치 · 워터마크 ·
**명명 스타일**(제목1 정의 수정).

명명 스타일은 가장 깊은 변경이다 — 지금 IR은 전부 인라인 스타일이라 도입하면
`doc-styles` 헤드 블록 + `class` 참조가 생기고 **세 백엔드의 스타일 등록기가 전부 바뀐다.**
1·2군을 끝내 `ir-model.ts`의 중립 트리가 두꺼워진 뒤에 결정하는 편이 정보가 많다.

## 범위 밖

공유 · 실시간 공동편집 · 댓글 · 제안 모드 · 스마트 칩 · Gemini. 서버와 계정이 전제이고
hwpx·docx·odt 어디로도 나갈 표현이 없다. "파일이 서버로 안 올라간다"가 이 프로젝트의
전제라 이 축을 쫓으면 다른 제품이 된다.

두 개만 예외로 볼 만하다 — **버전 기록**(로컬 IndexedDB 스냅샷으로 축소 가능)과
**문서 비교**(모든 블록에 `data-id`가 있어 오히려 우리가 유리하다).
