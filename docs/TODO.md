# 남은 일

구글 문서를 기준선으로 삼은 작업의 현재 위치. 전수 목록과 근거는
[GDOCS-FEATURES.md](GDOCS-FEATURES.md), 어휘 계약은 [IR-SPEC.md](IR-SPEC.md)에 있다.
이 문서는 **다음에 무엇을 어떤 순서로 할지**만 담는다.

기준선 18개 중 **6개 완료** (v0.2). 링크 · 첨자 · 문단 여백 · 페이지 설정 ·
서식 지우기 · 낱말 수 · 개요 레일, 그리고 계획 밖이었지만 필요했던 **읽기(Rust 리더 5종)**.

형태 표기는 GDOCS-FEATURES.md와 같다 — **A** 새 어휘 · **B** 속성 · **C** 백엔드 ·
**D** 편집기 · **E** 뷰어.

## 1. 바로 다음

### 05 각주 삽입 UI · **D** · 반나절

**IR·리더·쓰기·린터가 전부 완비인데 툴바 버튼만 없다.** `doc-footnote`는 IR-SPEC에서
✅ RW이고 `validateIR`에 `footnote-pair` 규칙까지 있다. 1군에 넣어놓고 빠뜨린 항목.

- 삽입 툴바에 버튼 → 캐럿 자리에 `<sup><a data-fn-ref="fnN">`, 섹션 끝에 `<doc-footnote id="fnN">`
- 번호는 **저장하지 않는다** — 뷰어 CSS counter가 그린다(BASE_CSS에 이미 있다)
- 참조를 지우면 짝도 지운다. 어긋나면 `footnote-pair`가 잡는다
- 건드릴 곳: `src/App.tsx`만

### 07 목록 numbering · **C** · 크다

**지금 저장하면 `"• "`가 본문 글자로 박힌다** (`html2hwpx.ts`의 `prefix`, docx·odt도 같음).
hwpx로 저장해 한글에서 열면 목록처럼 보이지만 목록이 아니다 — 항목을 추가해도 기호가
안 붙는다. 왕복 충실도가 존재 이유인 도구에서 가장 아픈 구멍.

- 세 포맷 모두 **문서 전역 numbering 정의 테이블**을 요구한다
- docx는 `numbering.xml` 파트가 아예 없다 → 새 파트 생성기 필요
- hwpx는 `header.xml`에 charPr/paraPr/borderFill 등록기가 이미 있다 → 같은 자리에 얹는다
- 딸려 오는 것: 목록 수준(중첩). 지금 `li`는 평평하다

### 08 개요 번호 · **B**+**C** · 07 직후

**07과 같은 인프라를 쓴다. 순서를 뒤집으면 두 번 만든다.**
`ir.ts`의 `H1: new Set(['data-num'])`이 이미 슬롯이고, IR-SPEC 규칙 2가
"번호는 파생물이라 저장하지 않는다"고 못박아 뒀다.

- 한글 공문서 관행 `1. → 가. → 1) → 가)`를 기본 프리셋으로
- 이게 들어와야 **개요 레일이 가져온 문서에서도 채워진다** (지금은 리더가 `h1~h6`을
  안 만들어서 편집기에서 제목 스타일을 준 것만 잡힌다)

### 09 표 셀 테두리 · 세로 정렬 · **B**

`STYLE_PROPS`에 `border`·`vertical-align` 추가. **hwpx는 절반이 되어 있다** —
`html2hwpx.ts`의 `borderFill` 등록기가 원래 테두리와 배경을 함께 담는 구조인데
지금은 `hc:winBrush`(배경)만 채우고 테두리 슬롯을 비워 둔다.

셀 배경은 IR·리더·백엔드가 이미 되는데 **편집 UI만 없다**(D) — 같은 팝오버에 같이 넣는다.

### 10 머리말 · 꼬리말 · 쪽번호 · **A** · golden file 선행

IR에 없던 개념(**필드**)이 들어온다 — `<doc-field data-kind="page|pages">`.
쪽번호는 텍스트가 아니라 렌더 시점에 계산되는 값이라 규칙 2를 그대로 따른다.

- hwpx 매핑 신뢰도 ◐ → **한글에서 꼬리말+쪽번호만 넣고 저장한 파일**로 확정한 뒤 착수
- `paginate.ts`가 만든 **페이지마다** 그리되 저장 전 `unpaginate`에서 걷어내야 한다
  (안 그러면 페이지 수만큼 중복 저장). 각주의 `TAIL` 처리와 같은 패턴
- 영역이 생기면 본문 가용 높이가 줄어 **조판이 따라 움직인다**

## 2. 검증 부채

기능이 아니라 **확인이 안 된 것**. 지금 이 머신의 한계 때문에 막혀 있다.

| 막힌 것 | 필요한 것 | 풀리면 |
|---|---|---|
| 링크·첨자·여백을 외부 구현으로 열어본 적 없음 | `brew install --cask libreoffice` | docx·odt를 남의 구현으로 확인. README 실기기 표를 v0.2까지 넓힐 수 있다 |
| hwpx 하이퍼링크 **쓰기**가 강등 상태 | 한글에서 링크 하나만 넣고 저장한 hwpx | `hp:stringParam name="Command"` 문법 확정 → 강등 제거 |
| `.doc` 들여쓰기 sprm 미발화 | 들여쓰기가 있는 Word 97 문서 | `0x840F`/`0x8411` 검증 → README 표의 ◐를 ✓로 |
| 화면 회귀를 사람이 봐야 함 | — | `bun run shots`가 캡처·콘솔오류·표 컨텍스트 전환까지 보지만, **그림이 맞는지는 사람이 본다** |

`.hwp`·`.doc`의 하이퍼링크 읽기는 필드 구조라 미구현 — 검증 부채가 아니라 남은 기능이다.

## 3. UI 구조 — 새 기능이 요구하는 없던 영역

버튼이 아니라 **앱에 없던 화면 영역**이 필요한 것들. 개별 기능보다 이게 먼저 걸린다.

| 필요한 영역 | 무엇이 요구하나 | 걸리는 것 |
|---|---|---|
| 가로 눈금자 | 들여쓰기·탭 정지 | 배율이 iframe 안 `body.style.zoom`이라 크롬 쪽 좌표와 어긋난다 |
| 머리말·꼬리말 밴드 | 10번 | `paginate`가 만든 페이지마다 그리고 저장 전 제거 |
| 여백 경계선 | 여백 드래그 | 지금 `padding`만 있고 **눈에 안 보인다**. 10번의 선행 조건 |
| 셀 선택 상태 | 표 서식 일괄 적용 | 지금 "셀 선택" 개념 자체가 없다 — 캐럿만 있다 |

**문서가 iframe 안에 있다**(`previewRef.contentDocument`)는 게 공통 제약이다. 문서 좌표에
붙는 UI(눈금자·표 핸들·링크 팝오버)는 좌표를 환산하는 대신 **오버레이를 iframe 안에 그리고
저장 직전에 걷어내는 쪽**을 권한다 — `paginate`/`unpaginate`와 `table-ui`가 이미 쓰는 패턴이다.

모달·팝오버 계층은 v0.2에서 만들어 뒀다(`.scrim`/`.dialog`/`.seg`). 표 서식·목록 옵션·
줄간격 팝오버가 그대로 재사용하면 된다.

## 4. 나중 (3군)

단(열) 나누기 · 목차 · 수식 · 도형/글상자 · 이미지 줄바꿈·위치 · 워터마크 ·
**명명 스타일**(제목1 정의 수정).

명명 스타일은 가장 깊은 변경이다 — 지금 IR은 전부 인라인 스타일이라 도입하면
`doc-styles` 헤드 블록 + `class` 참조가 생기고 **세 백엔드의 스타일 등록기가 전부 바뀐다.**
1·2군을 끝내 `ir-model.ts`의 중립 트리가 두꺼워진 뒤에 결정하는 편이 정보가 많다.

## 범위 밖

공유 · 실시간 공동편집 · 댓글 · 제안 모드 · 스마트 칩 · Gemini. 서버와 계정이 전제이고
hwpx·docx·odt 어디로도 나갈 표현이 없다. "파일이 서버로 안 올라간다"가 이 프로젝트의
전제라 이 축을 쫓으면 다른 제품이 된다.

두 개만 예외로 볼 만하다 — **버전 기록**(로컬 IndexedDB 스냅샷으로 축소 가능)과
**문서 비교**(모든 블록에 `data-id`가 있어 오히려 우리가 유리하다).
